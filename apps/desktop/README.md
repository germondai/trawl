# TRAWL desktop and Android (unreleased)

Tauri 2 with a static Nuxt/NuxtUI frontend. On desktop, the system WebView displays local controls and the native API dashboard. It does not run the scraping browser or keep a separate Nuxt server alive.

App settings → Language offers English, Čeština, Slovenčina, Polski, Deutsch, Français and System language (default). The application stores the choice on this device, independently of the selected server. Switching updates the interface, NuxtUI controls, native menu/tray and subsequent notifications without restarting the server or replacing request drafts, navigation history or downloads. All six catalogs are bundled offline in `packages/config/locales`; English supplies the fallback. Regional System preferences resolve to the first supported language (`cs-CZ` → `cs`), otherwise English. Technical setting names, API enum values, format names (Raw, HTML, JSON, Markdown and GraphQL), user content and original server diagnostics stay unchanged. Known local management and client errors are translated at presentation without changing their original protocol messages; visible errors follow language changes. Numbers and dates follow the selected language; detailed timestamps include the local time zone.

Android's UI and foreground-service processes read the same saved language. The notification/live-activity style and Stop/Restart actions keep their existing behavior. Android's own installer and filesystem dialogs use the OS language. This in-app preference does not add Android's separate OS per-app language selector. Existing explicitly saved instance names remain user data; new unnamed local instances use a translated default.

```sh
bun --cwd packages/runtime build
bun --cwd apps/desktop native:dev
# Platform package; macOS uses a local ad-hoc signature by default:
bun --cwd apps/desktop native:package
```

The macOS development bundle uses [Tauri's ad-hoc signing mode](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing) to seal its bundle resources. An explicit `APPLE_SIGNING_IDENTITY` overrides that default for a distribution build. Ad-hoc signing does not provide Developer ID trust or notarization; public distribution still requires the signing and installation checks in the v2 plan.

Browser tags share colors and explanatory tooltips: Recommended/Active are green, Latest blue, Repair ready teal, Needs repair/Deprecated orange, Unknown yellow, unsupported states red and Nightly violet. Installed/Not installed remain neutral. Catalog entries can explicitly set `deprecated: true` or `channel: "nightly"`; neither receives Latest or Recommended. The current verified catalog contains no deprecated or nightly entries. Beta version names do not imply Nightly, and unrecognized installations retain their existing unsupported/unknown status.

Selecting an instance keeps a closed window closed and preserves unsaved-edit confirmation in an existing window. The tray logo is gray while the local server is stopped and colored while it runs. Settings are grouped by topic, searchable across categories, and show readable units and inherited values. Standard/Economy presets remain opt-in. Runtime settings apply after restarting the server. Existing Docker installations are not modified.

New profiles keep running in the tray when the window closes. App settings also offers Ask or Quit; existing explicit preferences are preserved. Tray mode destroys the WebView to release its memory; Open TRAWL recreates it. Quit stops a server owned by this application, not one started by the CLI. Start at login and start the server with the application are separate, opt-in preferences under App settings. Smooth wheel scrolling is the last Application behavior preference. The stopped Overview and Requests pages fill the pane and center their setup/start action; page titles stay centered in the translucent pane header. Native window controls are aligned after AppKit completes a resize/layout, so individual traffic lights are not repositioned while AppKit is updating their siblings.

Saved connections can be renamed and reordered with the row arrows; the same names and positions appear in the app selector, command palette and numbered tray shortcuts. Saved remote connections provide dashboard access over the native API. Configure remote settings on the remote host. The desktop server keeps its loopback listener and cross-origin browser protection.

Use native controls for lifecycle checks. The frontend can also be previewed with `bun run dev`, but a browser preview cannot install or manage the native server. Run one heavy local build at a time with `CARGO_BUILD_JOBS=2` and check disk space first.

## Getting started and MCP

The first loaded native session offers a skippable localized app tour. A compact contextual card follows highlighted controls through real pages: navigation, instance selection, server lifecycle, request drafts, history, sessions, settings, search and refresh. It preserves drafts and settings, performs no requests or lifecycle actions, follows responsive layouts and supports reduced motion and Back/Forward. Tour collisions account for the visual viewport, native header controls and fixed phone navigation; targets are scrolled into the visible content area. Reopen it from the Application behavior header in App settings or the command palette. The tour follows the selected application language in English, Czech, Slovak, Polish, German and French. Cards use anchor-specific alignment, keep navigation controls visible while text scrolls, and temporarily make room below phone content to position the highlighted control higher. Closing the tour removes that space over 200 ms to avoid a scroll clamp jump; reduced motion removes it immediately.

MCP remains configurable in Server settings; there is no dedicated connection page. Session activity is paginated in pages of 20 on instances advertising `sessionActivityPagination`; older instances retain local paging of their latest 50 records. Session script activity refreshes every five seconds while its page is visible and the instance is healthy, and participates in global page refresh. Background updates preserve the selected script detail. Its footer explains retention and the separation from completed request timing.

## Request diagnostics and session activity

New request details show measured tier/cache/browser-acquisition/WAF spans, safe tier reason codes and first-class session/operation metadata. Nested and parallel spans overlap; their durations are not summed. Missing older measurements stay marked as unrecorded. Content presence and engine success do not prove that the returned page contains the caller's expected data. HTTP 403/429 without a detected challenge is shown as suspected blocking. The local Android runtime records its HTTP/WebView attempts and acquisition spans, including interrupted operations.

On instances advertising `sessionActivity`, Sessions shows the instance’s separate eval operations in a request-style table. Clicking the session name opens metadata and a bounded JavaScript code block. New eval records optionally carry `requestId`: the request owning the retained page, captured under the session lease after a successful page operation. Failed navigation/setup leaves uncertain page ownership unassigned. The `sessionActivityRequestIds` capability advertises support for request-scoped filters; older instances keep their activity available only in Sessions. A request’s Initiator view queries that exact ID, so later requests in the same session do not inherit earlier scripts. Older unlinked records remain in Sessions and are never assigned by timestamps. Request details keep the summary above all tabs and edit/replay and copy icons in the dialog header. Payload is offered only for methods with request bodies. Response groups the isolated HTML preview, derived Markdown, Raw source and available screenshots. Response headers and engine cookie snapshots are retained under the existing opt-in request capture policy and byte limits; older records keep missing values explicit. Derived Markdown uses retained HTML without contacting the target and is offered only by instances advertising `captureMarkdown`. Later scripts never change completed scrape timing or counters. Metadata contains session identity, timestamp, duration, outcome, source byte count and hash, without expression, return value or raw error text. Script source is retained only under the existing `HISTORY_CAPTURE_REQUESTS` policy/quotas and is downloaded through bearer-protected, retained-activity capture routes. Source previews are escaped and limited to 65,536 characters; full artifacts remain subject to the existing download limits. Activity retains at most 5,000 operations for 30 days and is excluded from anonymous dashboard metrics. Android-local instances do not offer persistent browser sessions/eval.

## Application updates (release setup)

App settings checks the official `app-updates.json` attachment on the latest GitHub Release. Desktop downloads are verified with the public key in `src-tauri/tauri.conf.json`; installation stops owned work and restarts the application. On Android, Download update opens the official APK in the browser. Open the downloaded APK to install it through Android's system installer. Android checks the signing identity when updating an existing installation. Keep the same Android signing identity between releases.

Create desktop updater bundles with `bun --cwd apps/desktop native:update:package`, setting `TAURI_SIGNING_PRIVATE_KEY` to the protected key path and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` when required. The private key is not stored in the repository. Back it up securely; replacing the configured public key breaks updates for existing installations. Normal development packages do not require this signing key.

On Linux, use the system package manager for manual `.deb` upgrades. The feed selects signed `.deb` and AppImage updates by the installed package format. For a direct release, test a clean install and an upgrade on each advertised package format. Verify the updater with the previous installed version, the exact release bytes, and the configured signing key. Keep the GitHub Releases feed available to existing clients if a future release moves the update endpoint.

For an approved release, collect and rename signed artifacts as `TRAWL_VERSION_TARGET.EXT`, with targets `darwin-aarch64`, `darwin-x86_64`, `linux-aarch64`, `linux-x86_64`, `windows-aarch64`, `windows-x86_64`, `android-aarch64`, or `android-armv7`. Extensions are `.app.tar.gz`, `.AppImage`/`.deb`, `.exe`/`.msi` and `.apk`. The generator adds `-appimage` or `-deb` to Linux feed keys. Keep each detached `.sig` beside its package; APKs also need a detached updater signature for the shared feed format. Run `bun apps/desktop/scripts/update-feed.ts VERSION ASSET_FOLDER app-updates.json [NOTES_FILE]`, review it, then attach the feed and matching artifacts to that approved `vVERSION` release. This script does not publish anything. Until the first feed is published the app reports that explicitly.

## Instance DNS

Server settings → Network & proxies → Instance DNS selects system DNS, Cloudflare, Google, Quad9 (threat-blocking/unfiltered), AdGuard (filtered/unfiltered), or custom servers for this local instance. Save and restart after changing it. System DNS and VPN configuration are never modified. HTTPS presets use standard DNS wire messages with pinned bootstrap IPs and normal TLS verification. The DNS editor combines provider selection and up to four separate custom server rows. The underlying `DNS_SERVERS` configuration remains comma-separated IP addresses (optional port, bracketed IPv6 ports) or HTTPS DoH URLs. DoH describes the resolver transport; both HTTP and HTTPS target websites are supported. IP endpoints use unencrypted DNS over TCP; custom HTTPS hostname bootstrap uses system DNS only to locate the resolver. Resolver failures do not fall back to ISP DNS, and valid NXDOMAIN/NODATA filtering is not retried through a different server. The five-second query budget is divided across configured endpoints.

Local `.local`/`localhost` names retain system resolution. Existing upstream proxies retain their own destination DNS. Public-only requests validate all selected addresses before dialing. Android's app-only WebView proxy is serialized across renderer cancellation and service recreation; custom-DNS rendering rejects a configured device HTTP/PAC proxy instead of silently replacing it.

## Input and navigation

Hold a request tab for 300 ms to drag it horizontally; Alt+Left/Right moves a focused tab with the keyboard. Desktop Cmd/Ctrl+F searches visible workspace text with next/previous matches. The find box excludes sidebar content and form input values. Desktop trackpad navigation uses native macOS finger/momentum phases and a wheel-idle fallback on other platforms, while leaving editable and horizontal-scroll surfaces alone. Once horizontal navigation owns a gesture, it consumes vertical drift through release, including momentum.

Phone drawers can be swiped from their body as well as their handle. A swipe that starts by scrolling stays a scroll until release, even at an edge. A new swipe beginning at the edge can drag the drawer. Input fields and sliders retain their own gestures. Upstream proxy URLs can be edited one per line in an expanded dialog/drawer, while saving still belongs to that instance's Server settings.

On phones, pull down from the top of the workspace to refresh its data; reversing or releasing before the indicator threshold cancels the refresh. Start/Stop remains in the header menu with distinct action colors.

Restarting from the Android notification recreates the notification after the server restart completes while keeping the service in foreground throughout. This may also recreate or briefly collapse Xiaomi HyperIsland presentation; check this sequence first if island continuity regresses.

## Private phone connections

For a simple private connection, use Tailscale on the host and phone, keep TRAWL’s host port on `127.0.0.1:8191` (publish the Docker host port there when using a container), then run `tailscale serve --bg 8191` on the host. Save the resulting private HTTPS `*.ts.net` address and the TRAWL API token in the phone. Restrict tailnet access to the intended devices. Tailscale Serve is tailnet-only; Funnel is public. See [Serve documentation](https://tailscale.com/docs/reference/examples/serve).

Cloudflare Tunnel + Access is another option, but Access browser login or service-token headers need an explicit client integration; a tunnel URL alone is not access control. No tunnel is provisioned by this application.

## Android runtime

Phones use a five-item bottom navigation with New request in the center; Tools and Settings open dismiss-only menus. The outer desktop workspace frame is omitted. Native content respects system bars, display cutouts and keyboard insets. Android TV is identified by the native Activity and keeps the desktop sidebar with visible keyboard/D-pad focus. App settings chooses whether the desktop sidebar toggle collapses to icons or hides the sidebar completely; opening and closing remain a two-state action.

Tooltips are available for hover and keyboard navigation. Touch controls show a short-lived hint after a 500 ms hold; releasing that hold does not activate the action. Actions, page navigation, scrolling and backgrounding dismiss open tooltips. Controls are not text-selectable; editable fields, request/response data, logs and useful prose remain selectable with the app accent. New request shows live elapsed time until completion or cancellation.

The Android adaptive icon uses the original transparent mark inset on a dark background to keep it inside launcher masks. Launchers control the outer icon shape; transparency of the foreground does not force a transparent launcher tile. App settings includes an Android settings action for device-specific background/battery restrictions.

`bun --cwd apps/desktop android:build` builds separate `arm64-v8a` and `armeabi-v7a` APKs (Android 7/API 24 or newer). Set `JAVA_HOME` to JDK 21, `ANDROID_HOME` to the Android SDK and `NDK_HOME` to its NDK. Install Rust targets `aarch64-linux-android` and `armv7-linux-androideabi`. The checked-in Gradle project uses API 36; builds generate their shared settings catalog before bundling the frontend. Release APKs need your signing configuration before distribution.

Android runs a portable Rust HTTP server and uses Android System WebView for JavaScript rendering. Camoufox, its desktop download catalog and its anti-detection behavior are unavailable on Android. HTTP tier 1 and fresh WebView tier 3 are supported, with four concurrent requests and one renderer. Responses are limited to 4 MiB; text request bodies to 512 KiB. The API provides `/scrape`, `/read`, `/extract`, basic `/v1` requests, metrics, logs and 200 retained metadata-only history entries. Read output is plain document text. Cookie output is currently available only from WebView, with limited cookie attributes. Persistent browser sessions, residential/proxy tiers, target Auth, input cookies, binary bodies, captures, inspection and desktop solver integrations are unavailable and are rejected explicitly. Remote connections can still use capabilities supplied by their server.

Server settings lists only categories present in the selected runtime's catalog. Android's local categories cover API requests and instance DNS; connecting to a full remote instance exposes the settings that server supports.

The Android listener defaults to `127.0.0.1:8191` with a randomly generated private Bearer key. Server settings lets you replace `API_KEY` with a known key of at least 16 characters for another client; credentials stay in app-private storage. Set `HOST` deliberately to expose the server on a trusted network. TLS verification stays enabled for outgoing HTTPS requests. Android history/log views use bounded polling when streaming events are unavailable.

Starting the server or a request starts a foreground service. Its notification shows request counts and Stop/Restart actions while the server runs; dismissal is followed by an update while work remains active. Home and Back keep the Activity in the background and do not cancel native requests. Removing the recent-app task keeps active foreground work on standard Android. If Android restarts the sticky service after reclaiming its process, the service restores the last explicitly started server without launching an Activity. The `:runtime` process owns the server and a separate WebView data directory; the interface uses a private, same-UID Binder connection rather than owning a second core. Killing only the interface process does not terminate that listener. Explicit Stop/quit clears the persisted intent. A finished workbench request sends a system notification when the Activity is not visible; ordinary data reads do not. Desktop browser downloads also send background completion/failure notifications. Notification permission and the operating system's channel settings determine whether those notifications appear. Force-stop cannot be overridden. Unfinished requests are not a durable job queue and are not automatically replayed after process loss. Device battery-management policies can still stop background work; allow unrestricted battery use in Android app settings when required. Resource figures include the runtime process, not the interface or separate WebView renderer processes.


Phone pull-to-refresh progressively draws its icon, spins while refreshing, then retracts; the header options remain available. Server notifications keep their URL in the header only, request Android promoted Live Updates with Stop/Restart actions, and retain Xiaomi HyperIsland integration. Restart freezes the prior notification until the successful reset instead of showing a restarting state.

Android App settings → Notifications controls live activities, enabled by default. Android promoted Live Updates and Xiaomi Focus cards stay expanded by system design; disabling live activities uses an ordinary, collapsible server notification, with Stop/Restart in its expanded view. Changing this preference immediately recreates the notice without restarting the server. The small information icon checks device support.
